## MCP Integration

Two Unity MCP servers are registered in `.mcp.json`, both bridging to the **same** running
Editor:

| Server | Transport | Bridge Port | Tools | Use for |
|---|---|---|---|---|
| `unity-pipeline` | `unity mcp` (stdio) | 7800 | 142 | Settings, builds, tests, assets, scene graph, profiling |
| `coplay-unity` | `uvx mcpforunityserver==10.1.2` | 6400 | 47 | Script editing, asset/AI generation, ProBuilder, UI |

Tool prefixes are `mcp__unity-pipeline__*` and `mcp__coplay-unity__*`.

> **Naming caveat:** the bundled agents in `.claude/agents/` declare `mcp__unityMCP__*`, and
> `.claude/settings.json` lists a `unityMCP` server at `http://localhost:8080/mcp` that is
> **not running**. Those agents will not receive Unity tools under the current server names.
> Either rename a server to `unityMCP` or update the agent frontmatter before relying on
> them.

**CLI equivalent** (same Pipeline bridge, useful in scripts):
```powershell
unity status                        # list connected editors
unity list                          # list all 142 tools + schemas
unity command get_scene_hierarchy
unity command create_gameobject --name Foo --primitive quad --parent "/TrainingArena"
```
Args are `--flag value`. **Run these from PowerShell** — Git Bash rewrites `/Main Camera`
into a filesystem path and the call fails.

## ML-Agents Workflow

```powershell
.venv\Scripts\activate
mlagents-learn Assets/Config/porumble_ppo.yaml --run-id=porumble_001
# then press Play in the Editor
```

- Behavior name in the config is `PoRumbleAgent` — it must match the **Behavior Parameters**
  component on the agent prefab exactly.
- A commented **self-play** block is in the config for agent-vs-agent brawler training.
- Trainer listens on port 5004; TensorBoard reads from `results/`.
- **Version pairing:** Unity package 4.1.0 pairs with pip `mlagents` 1.1.0. The numbers look
  mismatched but both speak communicator API **1.5.0**. Do not "fix" this — there is no newer
  `mlagents` on PyPI.
- `setuptools` must stay `<81` in `.venv`; 81+ drops `pkg_resources` and breaks the trainer.

Nothing in the scene has an `Agent` subclass yet — `Agent_A`/`Agent_B` are physics bodies
only. Training requires a C# `Agent` with `CollectObservations` / `OnActionReceived` plus a
`BehaviorParameters` component.

## Coding Rules

Full rules live in `.claude/rules/` and are authoritative:

| File | Covers |
|---|---|
| `architecture.md` | MVS pattern, VContainer DI, MessagePipe, UniTask, no singletons |
| `csharp-unity.md` | Naming, `[SerializeField] private`, encapsulation, `sealed` by default |
| `performance.md` | Zero GC in Update, draw calls, **sprite atlases**, batching |
| `serialization.md` | `[FormerlySerializedAs]` on every rename, Unity null checks |
| `unity-specifics.md` | Editor vs runtime, the `?.` trap, lifecycle, Input System |

Highest-frequency rules to remember:

- **Never use `?.` on a UnityEngine.Object** — it bypasses the destroyed-object check. Use `== null`.
- **Always add `[FormerlySerializedAs]`** when renaming a serialized field, or Inspector data is silently lost.
- **No legacy Input** (`Input.GetKey`/`GetAxis`) — blocked by hooks. Use the Input System via an `InputView`.
- **No coroutines** — the rules require UniTask (see the gap above).
- **`private` by default.** Do not create speculative public API or add `[SerializeField]` unless a designer tunes it.
- **Sprite atlases are mandatory** for 2D. None exist yet in `Assets/Art/Atlases/` — create them before adding many sprites.
