Who can do what, and what is kept

PoRumble has no login. There are no accounts, no passwords and no security passes, because the game runs on one device for whoever is holding it and never talks to a server. What it does have is a strict set of house rules about when each action is allowed.

Accounts and passwords

None exist. Nothing asks who you are.

Personal data collected

None. The saved files hold fighter ratings, play-money totals and fight statistics.

Data sent off the device

None. The game code makes no network calls.

Real money

None. The bank is play points that refill for free when they run out.

The Visitor Badge auth tokens
Not used. Think of a board game on your kitchen table: whoever is sitting there can play. Proposed / Not Yet Implemented: sign-in, user profiles, cloud saves, online leaderboards.
The Security Checkpoint request guards
This does exist, in a different form. Every request passes the front desk, which checks one thing: is this allowed on the screen we are on right now? In code: the phase guards on MatchFlowSystem and PredictionSystem.
The Filing Cabinet storage
Three plain files in the app's own data folder. Anyone with access to the device's files can read or edit them. They are not locked because nothing in them is worth locking.

What is saved, and where

Four kinds of file are written to the app's private data folder. None contains a name, an address, a device ID or anything else about you.

FileHoldsPersonal data?If it is damaged or missing
porumble_ratings.jsonEach fighter's rating, matches, wins and knockoutsNoOne warning; ratings start fresh
porumble_predictions.jsonPlay-money bank and pick totalsNoOne warning; bank starts at 1,000
matchlog/matches_<date>_<process>.jsonlOne line per finished match: time, winner seat, per-seat punch statisticsNo. A UTC timestamp is the only non-game valueThe line is skipped; the game carries on
perf/ CSV filesFrame-time measurements per match, newest 20 kept by defaultNoNot required by the game
  1. When a match ends, the rules hand the new totals to a "store" through a two-word contract: load and save. Rules
  2. The store writes the new file beside the old one, then swaps them, so being interrupted mid-save cannot leave a half-written file. Files
  3. If reading or writing fails for any reason, the game logs one warning and continues. A save file is never allowed to stop the game from starting. Files
